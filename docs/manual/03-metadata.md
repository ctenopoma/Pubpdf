# 文書情報の書き方

## frontmatter とは

原稿の先頭で `---` に挟んだ YAML の部分を frontmatter と呼びます。文書の情報と設定は、すべてここに書きます。

```yaml
---
title: 製品仕様書
subtitle: 基本設計編
author: 開発チーム
date: 2026-11-06
version: "1.2"
doc-number: DOC-001
pubpdf:
  cover: formal
---
```

## 書ける項目

| キー | 内容 | 表示される場所 |
|---|---|---|
| `title` | 文書名 | 表紙か1ページ目の先頭、PDF のプロパティ |
| `subtitle` | 副題 | 表紙か1ページ目の先頭 |
| `author` | 著者。複数ならリスト | 表紙か1ページ目の先頭、PDF のプロパティ |
| `organization` | 組織名 | 表紙か1ページ目の先頭 |
| `date` | 発行日 | 表紙か1ページ目の先頭 |
| `version` | 版数 | `formal` の表紙 |
| `doc-number` | 文書番号 | `formal` の表紙 |
| `abstract` | 概要。Markdown で書けます | 概要のページか、1ページ目の題の下 |
| `keywords` | キーワード。文字かリスト | PDF のプロパティ |
| `subject` | 主題 | PDF のプロパティ |
| `history` | 版ごとの変更の記録 | バージョン履歴のページ |
| `approval` | 承認欄の役割、名前、日付 | 表紙か1ページ目の題の下 |
| `lang` | 言語。既定は `ja` | 図や callout の名前(目次の題、「第1章」、表紙の項目名は日本語のまま) |
| `pubpdf` | ツールの設定 | [設定一覧](04-settings.md)を参照 |

: frontmatter の項目 {#tbl-keys}

`title`、`subtitle`、`version`、`doc-number` は Markdown として読みます。`author`、`organization`、`date`、`keywords`、`subject` は、書いたとおりの文字で出します。`date` に `today` と書くと、組んだ日の日付になります。

::: {.callout-tip title="版数は引用符で囲む"}
`version: 1.10` と書くと YAML が数値として読み、`1.1` と表示されます。`version: "1.10"` のように引用符で囲んでください。
:::

複数の著者は、次のように書きます。

```yaml
author:
  - 開発チーム
  - 品質チーム
```

`keywords` と `subject` は、PDF を開いたアプリの「プロパティ」に出る情報です。ページには出ません。`keywords` は、リストか、`,` や `、` で区切った文字で書きます。

```yaml
keywords: [仕様書, 製品A]
subject: 製品 A の基本設計
```

## バージョン履歴

`history` に履歴を書くと、表紙の次に「バージョン履歴」のページが入り、その次に目次が続きます。

```yaml
---
title: 製品仕様書
version: "1.1"
history:
  - version: 1.0
    date: 2026-10-01
    changes: 初版
  - version: 1.1
    date: 2026-11-06
    changes:
      - 第2章を追加
      - 誤字を修正
pubpdf:
  cover: formal
---
```

| キー | 表の列 | 内容 |
|---|---|---|
| `version` | 版 | 版の番号 |
| `date` | 日付 | 変更した日 |
| `changes` | 変更内容 | 変更の内容。リストで書くと 1 項目ずつ改行します |
| `author` | 作成者 | 変更した人 |
| `approver` | 承認者 | 変更を承認した人 |
| `note` | 備考 | 補足 |

: history の項目

- 表の列は、版、日付、変更内容、作成者、承認者、備考の順です。作成者、承認者、備考の列は、どれかの版に書いたときだけ出ます。行は書いた順に並びます。
- 設定の `history-number: true` で、表の左に 1 から数える項番の列を出します。
- 設定の `history-columns` で、列の順と見出しを決められます。列は `number`(項番)、`version`、`date`、`changes`、`author`、`approver`、`note` から選び、`version: バージョン` のように書くと見出しも変わります。指定した列は、値を書いていなくても出ます。
- 設定の `history-title` でページの題を、`history-blank-rows` で手書き用の空の行の数を変えられます。版を書いていなくても、空の行を指定すれば履歴のページを出します。

IPA の様式(項番、日付、バージョン、改訂内容、備考)にするときは、次のように書きます。

```yaml
pubpdf:
  history-title: 改訂履歴
  history-columns: [number, date, "version: バージョン", "changes: 改訂内容", note]
  history-blank-rows: 10
```
- 値は Markdown として読まず、書いたとおりの文字で出します。`history` の `version` は、引用符がなくても `1.10` のまま出ます。
- 表紙の版数は `version` から出します。`history` からは取りません。
- 履歴のページは目次に載りません。
- 表が 1 ページに収まらないときは、見出し行を繰り返して次のページへ続きます。
- 表紙がないときは、1ページ目の題の下に表を出し、目次は次のページから始めます。
- 合本では親 md の `history` を使います。章の md に書いても無視し、警告を出します。

## 承認欄

`approval` に役割ごとの名前と日付を書くと、表紙に承認欄を出します。役割の順に、左から右へ並びます。

```yaml
approval:
  - role: 承認
    name: 山田 太郎
    date: 2026-11-07
  - role: 審査
  - role: 作成
    name: 佐藤 一郎
    date: 2026-11-05
pubpdf:
  cover: formal
  approval-stamp: true
```

| キー | 内容 |
|---|---|
| `role` | 役割。必須です |
| `name` | 名前。書かなければ空欄です |
| `date` | 日付。書かなければ空欄です |

: approval の項目

- 役割は 8 個まで書けます。
- 設定の `approval-stamp: true` で、役割の下に押印や署名のための空欄を足します。名前も日付も書かなければ、指定しなくても空欄を出します。
- `formal` の表紙では文書管理情報の表の上に、`simple` の表紙では著者の下に出します。表紙がないときは、1ページ目の題の下に出します。
- 値は Markdown として読まず、書いたとおりの文字で出します。

## 概要

`abstract` に書いた内容を、「概要」の見出しを付けて出します。段落を分けるときは `|` を使います。

```yaml
abstract: |
  この文書は、製品の仕様をまとめたものです。

  第2章で、**画面の仕様**を説明します。
```

表紙かバージョン履歴があれば、それらの次のページに出します。ページの順は、表紙、バージョン履歴、概要、目次、本文です。どちらもなければ、1ページ目の題のすぐ下に出します。

概要の中の見出し、図、表、式は、本文の番号と目次に数えません。概要に画像は使えません。

## タイトルを書かないとき

`title` がなければ、次の順に題を決めます。

1. 最初の H1(`#` で始まる見出し)を題にします。
2. H1 もなければ、ファイル名を題にします。

合本では親 md の H1 だけを見ます。親 md に H1 がなければファイル名になり、章の H1 は使いません。

単一の md では、H1 の数で組み方が変わります。

| H1 の数 | 組み方 |
|---|---|
| 1つ | H1 を題に上げ、見出しを1段繰り上げます。`##` の見出しが章になります。目次があるときは、最初の `##` より前の本文が単独のページになります |
| 2つ以上 | H1 がそれぞれ章になります。`title` がなければ、最初の H1 は題と本文の両方に出ます |
| なし | `##` の見出しが章になります |

## 表紙がないとき

表紙を付けない文書では、1ページ目の先頭に題、副題、著者、日付を出します。目次もないときは、最初の章を同じページから始めます。

## 書き間違えたとき

未知のキーや使えない値があると、警告を出したうえで PDF を作ります。機密表示のキーを書き間違えても黙って表示が消えないように、警告は必ず確認してください。実際の表示では、ファイル名の部分は絶対パスになります。

```text
警告: sample.md:7: 未知のキー pubpdf.conficential は無視します
警告: sample.md:8: pubpdf.cover の値 "fancy" は使えません。既定値を使います
```

## frontmatter に書いても効かないもの

@tbl-keys にないキーは使いません。Quarto の設定(`format:` や `filters:` など)を書いても無視し、警告を出します。他の人から受け取った原稿で、意図しないプログラムが動かないようにするためです。本文の途中に `---` で囲んだ YAML を書いても、設定としては読みません。その部分は区切り線と文字として PDF に出るので、消してください。

```text
警告: sample.md:4: frontmatter のキー filters は使いません
警告: sample.md:7: 本文の途中の YAML は読みません
```

## 設定の優先順位

同じ項目を複数の場所で指定したときは、次の順に優先します。

1. 原稿の frontmatter
2. VS Code のワークスペースの設定
3. VS Code のユーザーの設定
4. 既定値

設定のキーの対応は、[VS Code での操作](07-vscode.md)にまとめています。
