# Pubpdf とは

Pubpdf は、Markdown の原稿から PDF を作るツールです。組版には Quarto と Typst を使いますが、それらの設定ファイルを利用者が書く必要はありません。

## できること

- 1つの md から1つの PDF を作る
- 複数の md を1冊にまとめる
- 表紙、機密表示、目次、ページ番号を設定で切り替える
- 文字の大きさ、行間、余白、用紙の種類と向き、見出しと図表の番号の形式を設定で変える
- frontmatter に書いた履歴と概要を、それぞれのページにする。表紙に承認欄と押印欄、二重の枠を付ける
- 設計書の形の表を組む(セルの結合と網掛け、2 段の見出し、セルの中の改行、HTML の表)。短い表は中身の幅に合わせられる
- 見出しの番号を「1. → 1.1 → (1) → ①」のような形にし、図表の番号を節ごと(表 1.1-1)に振る
- 参考文献を引用し、文献の一覧、図と表の一覧、付録を組む。脚注を参考文献の一覧にまとめ、一覧を置く位置も決められる
- 本文を段組みにし、ヘッダとフッタに文字を入れ、透かしと表紙のロゴを付ける
- テーマの色、表の体裁、コードの配色を選ぶ
- PDF の文書情報を指定し、PDF/A と PDF/UA で出力する
- 章を奇数ページから始め、綴じ代を取る(両面印刷や製本の前提)
- 表、コード(ファイルの参照、大きさに合わせた縮小と添付ファイルへの切り替え)、数式、定理、Mermaid の図(ほかの図と同じ配色にそろえる)、注意書きの囲みを組む
- ディレクトリ構造、グラフ、工程表、ビット配置、層構造、波形、作業分解、画面の模式図、JSON と YAML、ネットワーク、ユースケース、スイムレーンの業務フロー、FTA、帳票と画面の方眼、ER、画面遷移の図を描く
- テンプレート用の記入の指示の囲みを書き、仕上げるときにまとめて消す
- PDF にしおりを付ける(見出しから自動で作ります)
- フォントを指定し、OS に入れていないフォントも読み込む
- VS Code の中で作成、プレビュー、設定の変更をする

## 基本の考え方

原稿は Markdown だけ
: タイトルや著者などの情報は、原稿の先頭に YAML で書きます。設定ファイルを別に持ちません。

原稿は書き換えない
: 組版に必要な変換は中間コピーに対して行います。PDF を何度作っても、原稿は変わりません。設定パネルで変更したときだけ、frontmatter を書き換えます。

構成ファイルはツールが作る
: `_quarto.yml` やテンプレートは、毎回ツールが作り直します。同じフォルダに自分の `_quarto.yml` があっても、影響を受けません。

## PDF ができるまで

```mermaid
%%| label: fig-pipeline
%%| fig-cap: 原稿から PDF ができるまでの流れ
flowchart LR
    A["原稿の md"] --> B["内容の<br>確認"]
    B --> C["中間コピー<br>の作成"]
    C --> D["Quarto と<br>Typst で組版"]
    D --> E["PDF を<br>コピー"]
```

@fig-pipeline の各段階では、次のことを行います。

1. **内容の確認**: 設定の値を確かめ、章ファイルと画像があるかを確認します。誤りがあれば、ここで警告かエラーを出します。
2. **中間コピーの作成**: 原稿と画像を隠しフォルダに複製し、見出しへのリンクや Mermaid の記法を変換します。
3. **組版**: Quarto と Typst で PDF を作ります。
4. **コピー**: 完成した PDF を出力先へコピーします。

## 作られるファイル

| 場所 | 中身 | 扱い |
|---|---|---|
| `<原稿名>.pdf` | 完成した PDF | 原稿と同じフォルダに作ります |
| `.pubpdf/build/` | 中間コピー、`_quarto.yml`、テンプレート | 毎回作り直すので、消しても問題ありません。既定ではワークスペースのフォルダの直下に作ります |

: Pubpdf が作るファイル {#tbl-files}

中間ファイルの置き場所は、VS Code の設定 `pubpdf.buildDirectory` で選べます。`workspace`(既定)はワークスペースのフォルダの直下、`document` は原稿と同じフォルダ、`global` は拡張機能の保管場所で、プロジェクトのフォルダには作りません。ワークスペースの外の原稿は、原稿と同じフォルダに作ります。

Git で管理するときは、`.gitignore` に `.pubpdf/` の行を足しておきます。ワークスペースのフォルダが Git リポジトリなら、VS Code 拡張機能は最初に PDF を作ったときに追加するか尋ねます。
